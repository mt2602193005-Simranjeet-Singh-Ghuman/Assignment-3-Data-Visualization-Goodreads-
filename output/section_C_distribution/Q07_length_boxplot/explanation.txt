# Q07 — Median review length by spoiler group

## Question (from the PDF)
Compare the median review length between has_spoiler=True and has_spoiler=False groups in the boxplot. Which group has longer reviews, and why might that be the case?

## 1. Direct answer
The has_spoiler=True group has median length 1,333 characters versus 546 for False. has_spoiler=True is longer. Spoiler reviews tend to explain plot, so they run longer.

## 2. How long is the dataset, and what was left out?
The file on disk is **1.75 GB**, about **1.38 million reviews** (UCSD / Wan et al.: ~25,000 books, ~19,000 users, ~17.6 million sentences).

This run **kept the first 50,000 reviews** (`MAX_ROWS = 50,000`), which is about **3.62%** of the full set. That gave **16,589 books** and **558 users** in memory.

**What was not used, and how it was “removed”:**
- The remaining ~1,330,000 reviews were **never loaded**. The reader stops at `MAX_ROWS` and closes the file. Nothing is deleted from disk; we just stop reading.
- Why: a typical laptop cannot hold 1.75 GB of nested Python objects (that is Q3).
- Order: JSONL is read from the top, so this is a **first-N sample**, not a random sample. Early users can be over-represented (this run has only 558 users). That is a Q21 talking point, not a bug.
- Blank lines are skipped. Records with 0 sentences are **kept**, with `spoiler_ratio = 0.0` (Q5), not dropped.
- Scatter plots **draw** at most 8,000 points so the figure is readable; medians and correlations still use all 50,000 loaded rows.
- t-SNE uses a further wording subsample (about 2,000 reviews, and ~800 for the perplexity panel). The other loaded rows still feed histograms, boxplots, and the heatmap.
- There is **no book-title field** in this JSON. We did not remove titles; they were never in the metadata.

## 3. Workflow — how the code worked
1. Stream the JSONL file line by line (`json.loads` on one review at a time).
2. Stop at `MAX_ROWS`. The rest of the 1.75 GB file is unread, not deleted.
3. From `review_sentences`, build `n_sentences`, `review_length` (character count), and `spoiler_ratio = k/n` (0.0 if n is 0).
4. Keep the original metadata (`rating`, `has_spoiler`, `book_id`, …) next to those features in a table.
5. This question then does: review_length is computed per review, then matplotlib boxplot of the two groups. Median is the orange/navy line inside each box, also annotated.

## 4. How metadata was used
Fields named in this question: `has_spoiler`, `review_sentences`

For this question, each JSON field is treated as follows:
- `user_id` — **not plotted**. Who wrote the review. We only use it to count unique users in the footer. It is never an axis.
- `timestamp` — **not plotted**. The review date. None of the PDF questions are about time, so we leave it unused.
- `review_id` — **not plotted**. Unique id for one review. Used to count reviews per book. Not plotted.
- `book_id` — **not plotted**. Which book was reviewed. Needed for leaderboards, radar, and spoiler-prone ranking.
- `rating` — **not plotted**. Integer stars 0–5. Used whenever the question is about scores.
- `has_spoiler` — **used**. True/False for the whole review. Used for colour, boxplot groups, and t-SNE colour.
- `review_sentences` — **used**. List of [flag, text] pairs. This is where length, spoiler flags, ratio, and t-SNE text come from.

Derived features on the table: `review_length`, `has_spoiler`

## 5. Formula and working
- `median = middle value after sorting review_length in that group`
